1. Project Overview
OrgEventManager is a web application designed for campus student organizations to streamline event scheduling, live attendee roll-calls, and member participation tracking. It serves organization leaders (Officers) and general student attendees (Members), replacing manual paper rosters and chaotic social media chats with a structured, role-based platform.

Core feature for this increment: Event Creation & Attendance Tracking (RSVP)
Event Creation and Attendance Tracking represents the foundational core of an event management system, establishing the primary workflow where Officers publish campus activities and Members register attendance. Without the capability to schedule events and monitor RSVPs against venue capacity, subsequent modules such as attendance auditing, reporting, and certificate generation cannot function.

2.2 Core Feature: Event Creation & Attendance Tracking (RSVP)
Description:
This feature enables Officers to publish, update, and delete campus events with venue, schedule, and attendee capacity limits. It simultaneously allows Members to browse an active directory of upcoming activities, submit their attendance intentions (Going vs Not Going), and track their participation history, while preventing capacity overbooking.

User Roles and Access
| Role             | What this role can do in the feature                                                                             |
| Member (Student) | Browse upcoming events directory, view detailed event agendas, submit and update RSVP status, view RSVP history. |
| Officer (Admin)  | Create events, update event details, delete events, review management tables, inspect attendee rosters.          |

User Flow
Step 1: An Officer logs in and clicks "Create Event" on the Officer Dashboard or top navigation bar.
Step 2: The Officer fills in the event title, description, scheduled future date and time, venue, and attendee capacity, then clicks "Publish Event".
Step 3: The event is saved in the Supabase PostgreSQL database and immediately listed in the Officer Event Manager and Member Upcoming Events directory.
Step 4: A Member logs in, navigates to "Upcoming Events", and reviews the scheduled event with available seats remaining.
Step 5: The Member clicks "View Details", selects their attendance status ("Going" or "Not Going"), and clicks "Save RSVP".
Step 6: The system records the RSVP, decrements available capacity, updates the Member dashboard, and populates the live Attendee Roster visible to Officers.

Validation and Business Rules
| Rule                                      | How it is enforced                                                                                                                                   |
| Event date cannot be scheduled in past   | Enforced in EventForm clean_date_time(); raises forms.ValidationError if date_time < timezone.now().                                                 |
| Event capacity must be at least 1        | Enforced in EventForm clean_capacity() and PositiveIntegerField model constraint.                                                                    |
| One RSVP per user per event              | Enforced at the database level via unique_together = ('event', 'user') on the RSVP model and update_or_create logic in views.py.                       |
| Event capacity overflow protection        | Enforced in rsvp_event view; blocks 'GOING' submissions with an error flash alert when event.is_full is True.                                           |
| Strict role-based access control         | Enforced via @officer_required and @member_required view decorators; unauthorized access attempts are redirected to user's dashboard with an alert.   |
